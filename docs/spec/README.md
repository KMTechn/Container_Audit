## 2. 업무 흐름
1. **시작**: PC 를 켜고 로그온하면 이적 앱이 저절로 뜬다. 작업자 이름을 고른다.
2. **현품표를 찍는다**: 화면 가운데 위에 품목·수량(0/목표)과 「제품을 스캔하세요」 가 크게 뜬다.
   - 새 현품표: 회사 서버에서 그 현품표에 들어 있는 제품을 확인한다. 회사 서버가 끊겨 있으면 이 PC 에 저장하고 계속한다(확정은 다시 연결된 뒤).
   - 옛 현품표: 그 PC 의 「옛 현품표 받기」 가 켜져 있을 때만 받는다. 꺼져 있으면 「옛 현품표입니다 — 관리자에게 알리세요」 한 줄로 거절한다.
3. **제품을 하나씩 찍는다**: 맞으면 초록·짧은 소리, 수가 하나 오른다. 틀리면 빨강·오류음과 **무엇이 틀렸는지 한 줄**(다른 품목·이미 찍음·이 현품표에 없는 제품).
4. **수량이 차면 저절로 끝난다**: 긴 소리와 「완료 — 다음 현품표를 스캔하세요」. 완료 단추·확인 창은 없다.
5. **불량이 보이면 제품 교환**: 「교환」(명령 카드 또는 단추) → 불량 제품 찍기 → 대체품 찍기 → 끝. 창이나 완료 클릭이 없다. 대체품을 찍는 것이 곧 양품 등록이다(검사실에서 따로 찍지 않는다). 대체품이 검사 단계 다른 묶음에 있던 것이면 그 묶음에서 저절로 빠진다.
6. **수량을 못 채우고 마칠 때(드묾)**: 제품을 1개 이상 찍은 뒤 **같은 현품표를 다시 찍거나 「트레이 제출」 을 한 번** 누르면 미달 완료다(F-20). 관리자 확인은 없다. 60초 안에는 「마지막 스캔 취소」(명령 카드 포함)로 무를 수 있다(F-21).
   - 이적은 실제로 찍은 제품만 회사 서버에 보낸다. 회사 웹의 「미달 봉인」 길(웹 `service.py:11743-11830`·`packages.py:770-812`, webux sub-21 SIZE.md)이 이것을 받으므로 미달 트레이도 실물대로 이어진다. 포장은 실제 담긴 제품을 몰라 다르다(포장 명세 LM-17).
7. **잘못 찍었을 때**: 「마지막 스캔 취소」(명령 카드 포함, 마지막 한 건 — F-22). 처음부터 다시 할 때는 「현재 작업 리셋」(한 번 확인, F-23).
8. **잠시 멈추거나 넘길 때**: 「트레이 보류」 로 이 트레이를 그대로 저장해 두고 다른 현품표를 한다. 나중에 같은 현품표를 찍거나 「보류 N건 보기」 에서 고르면 이어진다(F-24·F-25).
9. **현품표 교체(F8)**: 수량이 바뀌어 현품표를 새 것으로 바꿀 때만 쓴다. 회사 서버 지시대로 새 현품표를 뽑아 붙이고 활성화한다. 뽑기가 불확실하면 실물을 확인한 뒤에만 다시 뽑는다(F-38–F-42). 제품 교환과 다른 일이다.
10. **회사 서버가 끊겨도 계속**: 입력을 막지 않는다. 바닥 줄이 「회사 서버 연결 안 됨 · 이 PC에 저장 중 · 보낼 것 N건」(주황)으로 바뀌고, 다시 연결되면 저절로 보낸다.
11. **진행 현황은 한 단계 안**: 「진행 현황」 단추 하나로 오늘 출고 계획 대비 남은 수를 별도 화면에서 본다. 작업 화면에 늘 띄우지 않는다. 그 화면에서도 스캔하면 작업 화면으로 돌아와 그대로 처리한다.
12. **하루 끝**: 따로 할 일 없다. 앱을 닫아도 저장된 기록은 다음 시작 때 이어 보낸다.

## 5. 회사 서버와 주고받기
| 무엇 | 언제 | 끊겼을 때 |
|---|---|---|
| 작업자 명단 받기 (`POST /api/worker-roster/v1/query`) | 시작·주기 | 마지막 정상 명단 |
| 기능 켜짐 확인 (`GET /logistics/api/v1/capabilities`) | 시작·배경 | 실패해도 「꺼짐」 으로 처리(CA-6) |
| 품목 목록 (`GET /inbound/api/item-catalog.csv`) | 시작·새로 받기 | 저장해 둔 목록. 확인 안 된 목록이면 시작하지 않음 |
| 현품표 목표·구성 조회 (`GET …/bundles/resolve`) | 현품표를 찍을 때 뒤에서 | 찍은 제품을 보존하고 30초마다 다시 조회. 다른 현품표 먼저 가능(최대 20) |
| **이적 기록(봉인)** (`POST /logistics/api/v1/transfers/seal`) | 이 PC 완료 뒤 | 이 PC 에 두고 같은 키로 다시 보냄. 회사 서버가 거절하면 그 트레이만 보류 |
| 제품 교환 (`POST …/bundles/{id}/replace-members`) | 교환 뒤 | 같은 요청으로 다시 보냄 |
| 대체품 확인 (`GET …/replacements/good-source/resolve`) | 대체품을 찍을 때 | 이 PC 교환 기록으로 진행 |
| 진행 현황 (`GET …/progress`) | 60초 | 마지막 값과 받은 시각 |
| 받았는지 다시 묻기 (`GET …/receipts/{scope}/{key}`) | 답을 잃었을 때 | 확인 전에는 새로 만들지 않음 |
| 현품표 교체(F8) 조회·준비·뽑기·활성화 (`…/phs-labels/…`·`…/phs-label-exchanges/…`) | 현품표 교체 때 | 진행 기록을 남기고 다시 조회. 불확실한 뽑기는 성공으로 치지 않음 |
| 관리자 PIN 확인 (`POST /api/admin-pin/v1/…`) | 관리자 동작 | 그 건만 보류 |
| 완료 기록 파일 (`POST /api/producer-ingest/v1/source-file`) | 기록 파일이 바뀔 때 | 이 PC 대기열(relay)에서 다시 보냄 |
| 다음 판 (`/static/update-feed/channels/container_audit/stable/latest.json(.sig)`) | 백그라운드 | 지금 판으로 업무 계속 |

- **작업자 이름**: 회사 서버가 「작업자 기록 신원」 기능을 켰다고 답할 때만 이적 기록에 작업자 번호·시작 때 이름을 붙인다. 모르면 붙이지 않고 보내며, 회사 웹은 그것을 받는다.
- **옛 현품표**: 「옛 현품표 받기」 로 끝낸 트레이는 회사 서버 이적 기록(봉인) 없이 기록 파일로만 올라간다.
- **새 현품표를 이 PC 에만 끝내면** 봉인이 없어 출고 사슬이 막힌다 → CA-1(포장 LM-1·웹 WEB-N1 과 짝).
- **C:\Sync 는 쓰지 않는다.** 옛 이적은 하루 기록을 C:\Sync 로 보냈다(Syncthing → 회사 서버). 새 이적 PC 의 하루 생산량은 그 웹 화면 합계에서 빠질 수 있다(COMPAT-TABLE :86 W2). 다시 넣을지는 사용자에게 물을 일이다(웹-b, w9mgrweb).

### 8-2. 주 흐름 한 바퀴 (실제 PC, 업무 밖)
1. 작업자 고르기 → 옛 현품표(스위치 켬) → 제품을 목표까지 찍는다. 저절로 끝나고 긴 소리가 나는지 본다.
2. 화면 캡처로 §3-1 다섯 자리(다음 할 일·N/목표·마지막 정상 스캔·커서·바닥 줄)를 1366×768·125 % 에서 판정한다(CA-3).
3. 메뉴·사진 보기·작업 상세를 연 뒤 다음 스캔이 들어가는지 본다(CA-02 초점).
4. 기록 파일 업로드 1건을 본다. 새 현품표 1 트레이는 랩 또는 시험 품목으로만 하고, 회사 서버 이적 기록(봉인 receipt)을 본다.
5. 교환 카드로 제품 교환 1번, 마지막 스캔 취소 1번, 같은 현품표 다시 찍기로 미달 완료 1번(60초 안 취소 1번).
6. 트레이 보류 → 다른 현품표 → 보류 복원.
7. 네트워크를 끊고 1 트레이 → 바닥 줄이 주황이 되는지 → 다시 연결 → 보낼 것이 0 이 되는지 본다.
8. 앱을 닫았다 켜서 이어 하기가 되는지 본다.
